
Фреймворк: FastAPI (высокая скорость, встроенная валидация данных через Pydantic, автоматическая документация Swagger).
База данных: SQLite + SQLAlchemy (или встроенный модуль sqlite3 для максимальной легковесности). 
Файл базы данных хранится локально в проекте (database.db).

API Эндпоинты
POST /api/lead — основной эндпоинт для приема заявок с фронтенда.   
Входные данные (Payload): name, phone, topic (подписка / разовый заказ / вопрос), comment, рекламные метки (utm_source, utm_campaign, page_url), ip_address, timestamp.
Валидация на бэкенде: Проверка телефона с помощью регулярного выражения для белорусских номеров, проверка заполненности обязательных полей.
Бизнес-логика защиты от спама: Проверка в таблице SQLite: если с данного номера телефона уже поступала заявка менее чем 10 минут назад, эндпоинт возвращает ошибку 400 Bad Request («Заявка уже отправлена, ожидайте звонка»).
Сохранение: Запись валидной заявки в таблицу leads.
Ответ клиенту: JSON с подтверждением успеха (200 OK) или описанием ошибки.

Структура БД:
id — Integer (Primary Key): Уникальный идентификатор заявки
name — Text: Имя клиента
phone — Text: Белорусский номер телефона (в формате +375...)
interest — Text: Что интересует клиента (подписка, разовый заказ, вопрос)
comment — Text: Дополнительный комментарий / пожелания
utm_source — Text: Источник рекламы (например, instagram, yandex)
utm_medium — Text: Тип трафика (например, cpc, social)
utm_campaign — Text: Название рекламной кампании
utm_content — Text: Идентификатор объявления / креатива
utm_term — Text: Поисковый запрос / ключевое слово
referrer — Text: Страница-источник перехода
status — Text: Статус обработки заявки (например, new — новая, processed — обработана)
created_at — Timestamp: Дата и время создания заявки
