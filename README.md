
# Отчет о разработке и работе с ИИ

# 1. Распределение задач (Человек vs ИИ)
Создано с помощью ИИ (Codex / Google AI Studio):**
Генерация первичного UI-каркаса и компонентов на Next.js + Tailwind CSS на основе дизайна.
Написание базового FastAPI бэкенда, Pydantic-схем валидации и SQL-запросов для SQLite.
Шаблоны конфигурационных файлов (`Dockerfile`, `docker-compose.yml`) и автоматических тестов `pytest`.
Сделано вручную:
Проектирование архитектуры монорепозитория и структуры базы данных.
Настройка интеграции фронтенда и бэкенда (передача UTM-меток из `sessionStorage` в API).
Проведение аудита производительности через Lighthouse (Mobile) и оптимизация продакшн-сборки.
Итоговая отладка, тестирование бизнес-логики (антиспам) и ручная проверка формата телефонов.

# 2. Ошибки ИИ и как они были обнаружены
Формат валидации номеров: При генерации Pydantic-схемы ИИ первоначально предложил базовую регулярку для международных номеров, которая пропускала некорректные белорусские операторы. Ошибка была замечена при ручном тестировании формы — регулярное выражение было скорректировано под строгое соответствие кодам `+375 (29|33|44|25)`.
Настройки CORS: ИИ не учел возможные блокировки при локальном связывании порта Next.js (`3000`) и FastAPI (`8000`). Ошибка проявилась в консоли браузера (`CORS policy error`), после чего вручную был добавлен `CORSMiddleware` с явным указанием доверенных `origins`.
Пути к БД в тестах: При генерации `pytest` фикстур ИИ попытался использовать основной файл базы данных, что перезаписывало тестовые данные. Заметив это в коде, мы переписали фикстуру с использованием `monkeypatch` для использования временного SQLite-файла.

# 3. Что не успели или сделали бы иначе
Улучшение работы с БД: В текущей реализации используется чистый `sqlite3` / легкий слой доступа. В реальном продакшн-проекте лучше перейти на SQLAlchemy / SQLModel** и настроить миграции через Alembic.
Автоматический деплой (CI/CD):Не хватило времени настроить GitHub Actions для автозапуска `pytest` и проверки Lighthouse при каждом пуше.
Расширенный мониторинг: Добавили бы логирование заявок через `structlog` и интеграцию с Telegram-ботом для мгновенного уведомления менеджеров о новых лидах.



# Kvarta Coffee
Лендинг для крафтовой ростерии кофе «Кварта» (г. Минск), разработанный в рамках тестового задания. 
Проект реализован в формате монорепозитория, объединяющего современный фронтенд на Next.js и высокопроизводительный бэкенд на FastAPI.

# Frontend Stack
1) Next.js: Выбран для создания SSR/SSG-ориентированного лендинга с быстрой первичной загрузкой, 
встроенной SEO-оптимизацией и удобной файловой маршрутизацией.
2) Tailwind CSS: Обеспечивает высокую скорость разработки, гибкость при кастомизации UI-компонентов и минимальный размер итогового CSS-бандла.
3) TypeScript: Гарантирует строгую типизацию данных (при работе с формами и API-ответами) и снижает количество ошибок на этапе разработки.

# Дизайн
1) Исследование на Pinterest: Перед началом разработки был проведен анализ референсов на Pinterest по запросам крафтовых кофейных брендов и спешелти-ростерий.
2) Визуальный стиль: В основу концепции легли теплые, глубокие кофейные оттенки, отражающие атмосферу уюта и премиальность продукта.
3) Современные тренды: Использована минималистичная типографика, крупная продуктовая сетка каталога, интерактивные карточки подписок и аккуратные микро-взаимодействия при заполнении формы заказа.

# Backend Stack
1) FastAPI: Легковесный и асинхронный Python-фреймворк, обеспечивающий высокую скорость обработки HTTP-запросов и автоматическую генерацию OpenAPI/Swagger-документации.
2) SQLite: Выбран как оптимальное встроенное реляционное хранилище для тестового задания и локального развертывания. Не требует дополнительного администрирования тяжелых СУБД, 
при этом полностью закрывает задачи надежного сохранения лидов и проверки ограничений.
3) Pydantic: Используется для строгой валидации входных данных (формат белорусских номеров телефонов `+375...`, корректность email и защита от спама).

## Запуск тестов бэкенда

Из корня проекта установите зависимости и запустите тесты:

```bash
python -m pip install -r backend/requirements-dev.txt
pytest
```

Тесты используют отдельную временную базу SQLite для каждого теста и не изменяют рабочую базу `backend/database.db`.

## Запуск через Docker

Из корня проекта выполните `docker compose up --build`, затем откройте `http://localhost:3000`.

# Функциональные особенности
1) Интерактивный просмотр кофейных сортов и условий регулярной доставки.
2) Валидация белорусских номеров телефонов и проверка заполнения обязательных полей.
3) Алгоритм ограничения повторной отправки заявок с одного номера/IP в течение 10 минут.
4) Отдельные ТЗ для каждого микросервиса расположены в директориях `frontend/frontend-tz.md` и `backend/backend-tz.md`.
